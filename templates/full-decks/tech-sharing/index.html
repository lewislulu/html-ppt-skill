deep-dive · 1 / 2

Future에는 실제로 한 가지 방법만 있습니다.

컴파일러 async fn 실현이 된다 Future 특성에 대한 익명 상태 머신. 실행 중에는 단 한 가지만 수행합니다: 반복 poll 돌아올 때까지 Ready.

Pending Ready(T) Waker.wake()
future.rs
pub trait Future {
    type Output;
    fn poll(
        self: Pin<&mut Self>,
        cx: &mut Context<'_>,
    ) -> Poll<Self::Output>;
}

// Poll::Pending → 정지, waker가 깨어날 때까지 기다림
// Poll::Ready(v) → 완료, v 출력

심층 분석 · 2/2

토키오는 일을 훔치는 일꾼입니다.

멀티 스레드 런타임 = N 작업자, 각 작업자는 자체 로컬 대기열을 갖습니다. 유휴 작업자는 다른 사람의 대기열에서 작업을 "훔칩니다".

✦ 로컬 대기열 · 256개 슬롯
✦ 전역 주입 큐
✦ 작업 훔치기 @ 50% 훔치기 비율
✦ 캐시 지역성을 위한 LIFO 슬롯

스케줄러 틱 루프

1. LIFO 슬롯에서 팝
2. 그렇지 않으면 로컬 대기열에서 팝
3. else 전역 대기열 비우기(61틱마다)
4. 그렇지 않으면 무작위 피해자에게서 물건을 훔칩니다.
5. 그렇지 않으면 스레드를 파킹

mini-runtime.rs · ~40 LOC

최소한의 런타임을 직접 작성하세요.

src/main.rs
use std::collections::VecDeque;
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Wake, Waker};

struct Task(Mutex<Pin<Box<dyn Future<Output = ()> + Send>>>);

impl Wake for Task {
    fn wake(self: Arc<Self>) { QUEUE.lock().unwrap().push_back(self); }
}

fn block_on<F: Future<Output = ()> + Send + 'static>(fut: F) {
    spawn(fut);
    while let Some(task) = QUEUE.lock().unwrap().pop_front() {
        let waker = Waker::from(task.clone());
        let mut cx = Context::from_waker(&waker);
        let mut fut = task.0.lock().unwrap();
        let _ = fut.as_mut().poll(&mut cx); // 이 줄입니다
    }
}

// 테이크아웃

세 가지 물건을 가지고 돌아가세요.

1 · 비동기는 비용이 들지 않는 추상화입니다.

상태 머신으로 컴파일되며 런타임 가상 테이블도 없고 GC도 없습니다.

2 · Waker는 펄스입니다

Future는 주도적으로 작업을 수행하지 않으며, Waker에 의존하여 런타임 중에 "다시 폴링할 시기"를 결정합니다.

3 · 비동기식으로 차단하지 마세요

std::fs::read 한 줄로 전체 작업자가 중단될 수 있습니다. spawn_blocking을 사용하세요.
